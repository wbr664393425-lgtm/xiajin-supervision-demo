# 阶段 D：信访研判纵向接入

**目标**：将用户已确认的“B案头入口＋A材料审阅”接入原有工程，实现可录入、可核对、可保存、可继续办理的单场景闭环。

**入口**：<http://127.0.0.1:5186/#/clues>。继续使用 `npm run dev`，生产构建 `npm run build`。阶段 B / C 设计预览继续保留在5174，没有覆盖设计稿。

## 实际接入

- 原生 Vue 案头、材料审阅与操作面板，无整页图片、iframe或原型HTML嵌入。新信访路由拥有独立壳层和局部样式；其他模块不批量改版。
- 新材料进入原 `platform.clues` 集合，分配不冲突的编号，保留输入的全部字符、空白与换行。TXT读取文件实际内容；图片/PDF不模拟成该附件的真实OCR结果。
- 每份线索有独立工作稿，保存于原平台同一持久化状态中的 `clueWorkspaces[id]`，当前案头材料为 `activeClueId`。旧缓存没有这些字段时使用空默认值，保留其他业务进度。
- 原文规则提取四类要素，记录来源偏移、原始提取值、人工修订与确认状态。样例会故意将“禾川”误提取为“禾田”，用于演示人工纠错。未提取到的信息需人工补正或注明未载明。
- 按完整合同编号检索相似材料，保留两份原件和高亮的匹配编号。每个候选分别作关联、暂不关联或待核决定，不删除或自动合并举报。
- 合同和收款依据从现有合同/收款集合读取。未关联到记录时明确显示空状态，不把其他样例金额套用到新材料。
- 保存摘要包含正文、字段及关联决定快照；回到案头或刷新后可重开。修改字段或关联决定后，旧摘要标记为待同步，必须重整或修订。
- 提交前需四项字段人工确认、全部相似候选已判断、当前稿已保存，并单独勾选人工检查。提交更新线索为“待复核”，等待复核人处理，不创建核查任务。后续修改撤回该提交，保留上次保存稿。
- 登记、提取、修订、关联、保存、提交等操作同时进入本件记录与原平台操作留痕。总览将“待复核”线索纳入待人工处理事项。已在其他阶段办理的旧任务不被重置。

## 建议验收路径

1. 打开案头 → 整理新材料 → 载入虚构样例 → 登记并开始阅读。
2. 查看原件 → 开始辅助提取 → 将“禾田”修正为“禾川农机服务社” → 对照原文确认其余三项。
3. 查看相似材料。新建同文样例通常会检索到原有0108与0106；逐份选择人工关联、暂不关联或标记待核。
4. 保存待复核摘要 → 返回案头 → 重新打开 → 刷新页面，确认正文、字段修订、关联判断和记录恢复。
5. 完成人工检查并勾选 → 提交人工复核。返回监督总览可看到更新的待处理状态；核查任务数量不因本操作增加。
6. 再次修改提取字段，查看提交撤回、旧摘要待同步及上次保存稿的保留状态。
7. 可另录一份只含“5,000元”的虚构材料，确认提取值只来自原文；缺少时间/主体时需补正。相似编号0189不能匹配018，合同编号不能作为日期。
