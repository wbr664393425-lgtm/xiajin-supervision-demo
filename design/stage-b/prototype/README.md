# 阶段 C · 案头与材料审阅原型

预览：<http://127.0.0.1:5174/prototype/>

从项目根目录启动（与阶段 B 共用设计预览服务）：

```sh
python3 -m http.server 5174 --bind 127.0.0.1 --directory design/stage-b
```

不需要安装额外依赖。它是独立的 HTML/CSS/ES Module 原型，未导入原系统的 Vue、Pinia、路由或数据库。保留原来 5173 服务。

## 体验路径

1. 默认是有一份未完成工作稿的案头。点击“继续整理这份工作稿”可直接续办。
2. 要从零开始，点击“整理新材料”→“载入虚构样例”→“开始阅读”。空状态不能直接开始，当前只接受统一的固定样例。
3. 在材料审阅页点击“开始辅助提取”。出现分析中状态，随后显示四条待确认批注。
4. 把承租主体由故意误提取的“禾田农机服务社”修订为“禾川农机服务社”；其余三项可定位原文后确认。点击原句编号可回到批注，收起批注后阅读区域扩大。
5. 打开“查看相似材料”，对照两份原件和匹配依据，选择“人工关联 / 暂不关联 / 标记待核”。任何选择均保留两份原件，不自动合并。
6. 打开“保存待复核摘要”，编辑摘要并保存。回案头可重新打开；刷新恢复此原型的本地工作稿。
7. 四项提取全部确认、关联判断完成且当前稿已保存后，才可勾选人工检查并提交复核。提交后显示“人工检查已完成，已提交复核”，表示等待复核人，不声称后续复核已完成。

## 状态边界

- 原件陈述始终保留；字段修订不会改写举报材料。
- 台账检索记录与 AI 辅助提取分别标示。人工确认的是整理文字，不是事项已查实。
- 保存允许未完成的工作稿；提交则有独立检查。保存不等于提交，更不等于创建正式核查任务。
- 提交后再次修订字段、摘要或关联决定，会使原提交失效，需重新保存与人工检查。
- 已有摘要后再修改字段确认或关联决定，会标为“摘要待同步”；需重整或修订摘要，禁止直接把未变的旧正文重新保存后提交。
- 右上角“演示专员”菜单可查看整理记录和重置此原型。缓存键 `xiajin-stage-c-prototype-v1`，与原系统状态隔离。
- 所有案例虚构；提取和检索是本地确定性模拟，没有真实 OCR、LLM 或外部数据接口。
