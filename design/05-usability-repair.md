# 信访场景：用户反馈后的修复

用户实际反馈：蓝底黑字、配色混乱、交互入口不明显。此前的业务测试与构建没有覆盖这些产品缺陷，不能代替可用性与视觉交付。

## 已修复

- 场景级 `.clues-scene button { color: inherit }` 的优先级高于组件主按钮，覆盖了白色文字、链接与选中标签。将基础重置降为 `:where(.clues-scene)`，保留组件自己的颜色与字号。
- 案头、阅读、对话框共用 `clue-tokens.css`：一个品牌蓝、统一正文与辅助文字、边线、确认色、禁用色。禁用控件不整体降低透明度，也不会悬停变成可用的深蓝状态。
- 未提取时底部主按钮可直接“开始辅助提取”；分析中显示进度，提取后进入整理摘要。右侧不再重复放一颗同权蓝色入口。
- 案头字段可点击进入对应原文批注；“核对下一项”只定位，不自动确认；相似材料可继续判断下一份，仍需逐份人工选择。
- 从合同/原件面板返回保留正在输入的字段内容，返回按钮名称与实际目的地一致。
- 摘要、来源和对照面板写入合法路由参数，刷新及前后退可恢复上下文；更换材料会重新校验，防止把旧摘要呈现到未提取的新材料上。
- 来件搜索随地址恢复；新材料的地域默认留空，由用户输入或载入样例。

## 验证

`npm test` 全部56项通过，其中新加入11项真实组件DOM与样式测试、6项页面点击与路由连续性测试。样式测试确实载入项目CSS，检查主按钮计算颜色、白色图标、文字对比度≥4.5、禁用状态及后加载重置样式的覆盖问题。页面测试经由实际控件完成新登记、提取、纠错、两个关联判断、保存与人工勾选后提交。

DOM引擎为Happy DOM，不是浏览器截图；不将这些测试声称为两轮视觉验收。用户此前选择自行页面验收，本轮未重试浏览器工具。

## 当前交付边界

已接入原工程的本地演示状态、原文、台账、保存快照和操作记录。真实OCR、大模型、生产后端数据库与账号权限没有接入。功能闭环已经实现，成熟产品的视觉与易用性仍须以实际使用反馈继续修正，不再以构建或测试数量替代结论。
