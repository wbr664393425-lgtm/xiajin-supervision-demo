# 夏津县纪检监察演示平台运维手册

## 入口与运行环境

打开[公网演示平台](https://br20.xiaoyuqi.top/)，手动输入既有账号和密码。登录后可进入[监督工作台](https://br20.xiaoyuqi.top/#/home/dashboard)、[线索督办台账](https://br20.xiaoyuqi.top/#/clues/ledger)或[纪检助手](https://br20.xiaoyuqi.top/#/assistant/chat)。同一次登录即可使用在线 AI。仅使用虚构材料进行演示，在线问答会将输入发送到已配置的模型网关。

部分网络无法连接默认 443 入口时，可使用[备用 HTTPS 入口](https://br20.xiaoyuqi.top:8443/)，账号与原入口一致。两个入口的浏览器演示记录按端口分别保存，原入口的 `localStorage` 记录不会自动迁入备用入口，也不会因此删除。

登录页不提示展示凭据。“记住账号”只保存账号名。服务端校验成功后签发 8 小时有效的 Secure、HttpOnly、SameSite=Strict Cookie；退出、过期或 API 服务重启后需重新登录。模型接口按客户端 IP 限速，最多同时向上游发起 4 个请求，并固定使用服务器配置的模型。上游不可用时，助手可回退到内置离线引擎。

演示进度在当前浏览器、当前域名的 `localStorage` 中（`xiajin-v2:` 前缀）。台账和文书需要从业务页导出留存。清除站点数据或使用「重置数据」会丢失该浏览器中的演示记录。业务日期固定为 `2026-11-07`，换汇报日期时修改 `src/stores/persist.ts` 并发布新版。

## 巡检与验收

在运维电脑执行。首页摘要应一致；新会话应返回 `{"authenticated": false}`，未登录的模型请求应返回 401。

```bash
ssh mobile 'cd /opt/wbr/xiajin-supervision-demo && readlink current && systemctl is-active nginx xiajin-supervision-api && ss -H -ltn "sport = :1020"'
ssh mobile 'set -o pipefail; curl -fsS http://127.0.0.1:1020/ | sha256sum'
(set -o pipefail; curl -fsS https://br20.xiaoyuqi.top/ | shasum -a 256)
curl -fsS https://br20.xiaoyuqi.top/api/session
curl -sS -o /dev/null -w '%{http_code}\n' -X POST https://br20.xiaoyuqi.top/api/llm/chat/completions
```

1. 在新浏览器窗口直达「线索督办台账」。登录页应无默认账号、密码提示或快捷填入按钮，输错密码应被拒绝。
2. 使用既有账号登录，应回到台账。生成初稿并刷新，页面应保持登录。
3. 「纪检助手」选「纪检大模型」并提交一条虚构问题，观察流式回复及完成初稿的「大模型」标签。侧栏在线提示仅说明连通性。
4. 退出登录，再次打开业务页应进入登录页。

在项目根目录使用 Bash 执行。生产构建必须指定 `--mode mobile`，它会移除本地模拟口令，使用服务端登录和模型接口。下列命令只上传构建文件和服务代码，模型配置单独保存在服务器。

```bash
set -euo pipefail
cd '/Users/wbr/Documents/project/夏津纪检监察'
id=$(TZ=Asia/Shanghai date +%Y%m%d-%H%M%S)
out=$(mktemp -d)
npm run build -- --mode mobile --outDir "$out/public"
base=/opt/wbr/xiajin-supervision-demo
COPYFILE_DISABLE=1 tar -czf - -C "$out" public -C "$PWD" deploy/mobile |
  ssh mobile "set -eu; cd '$base/releases'; umask 022; mkdir '.$id.upload'; tar --no-same-owner -xzf - -C '.$id.upload'"
```

同一终端继续执行版本切换。仅允许切换到含服务端登录的版本。切换过程中会重启本站 API，已登录的浏览器需要重新登录。

```bash
ssh mobile bash -s -- "$id" <<'REMOTE'
set -euo pipefail
cd /opt/wbr/xiajin-supervision-demo
exec 9>.release.lock
flock -n 9
id=$1
[[ $id =~ ^[0-9]{8}-[0-9]{6}$ ]]
stage="releases/.$id.upload"
old=$(readlink current)
test -s "$old/deploy/mobile/gateway.py"
test -s "$stage/public/index.html"
test -s "$stage/deploy/mobile/gateway.py"
assets=$(grep -oE '/assets/[^"]+\.(js|css)' "$stage/public/index.html")
for asset in $assets; do test -s "$stage/public$asset"; done
test ! -e "releases/$id"
mv -T "$stage" "releases/$id"
site=/etc/nginx/conf.d/xiajin-supervision-demo.conf
unit=/etc/systemd/system/xiajin-supervision-api.service
mkdir -m 700 "backups/$id"
cp -p "$site" "backups/$id/site.before"
cp -p "$unit" "backups/$id/unit.before"
printf '%s\n' "$old" > "backups/$id/previous"
switch_to() { ln -s "$1" ".switch-$$"; mv -Tf ".switch-$$" current; }
rollback() {
  sudo install -m 0644 "backups/$id/site.before" "$site"
  sudo install -m 0644 "backups/$id/unit.before" "$unit"
  switch_to "$old"
  sudo systemctl daemon-reload && sudo systemctl restart xiajin-supervision-api
  sudo nginx -t && sudo systemctl reload nginx
}
trap 'trap - ERR; rollback; exit 1' ERR
switch_to "releases/$id"
sudo install -m 0644 current/deploy/mobile/site.conf "$site"
sudo install -m 0644 current/deploy/mobile/xiajin-supervision-api.service "$unit"
sudo nginx -t
sudo systemctl daemon-reload
sudo systemctl restart xiajin-supervision-api && sudo systemctl reload nginx
curl -fsS --retry 4 --retry-delay 1 --retry-all-errors http://127.0.0.1:1020/api/session | grep -q '"authenticated": false'
curl -fsS http://127.0.0.1:1020/ | cmp - current/public/index.html
REMOTE
```

切换完成后执行「巡检与验收」。按上述流程同步网关和服务配置后，如公网业务出现异常，可在 `mobile` 的部署根目录取得同一把 `.release.lock`，从该次 `backups/版本号/previous` 读取原版本，并按上段 `rollback` 函数恢复版本、源站配置和服务定义。当前可回退的首个已验证服务端登录基线是 `releases/20261107-004432`。原始公网代理与证书沿用服务器配置。

## 故障处理与备份

| 现象 | 处理 |
| --- | --- |
| 全站 502 | 查 Nginx 状态、1020 监听及源站首页；本机正常时检查 br20 的 HTTPS 和 `proxy_pass`。 |
| 页面正常但登录失败 | 查 `systemctl status xiajin-supervision-api` 和 `journalctl -u xiajin-supervision-api -n 40 --no-pager`；核对 socket 和私有配置的存在及权限，避免输出配置内容。429 表示短时间登录尝试过多。 |
| 登录有效但 AI 回退离线 | 核对助手引擎选择和模型接口状态。401 时重新登录，429 时稍后重试，503 时检查模型配置是否装载，502 时检查网关网络、证书、模型权限和额度。 |
| 模型密钥更换或需暂停在线功能 | 由授权运维人员在服务器更新 root 专属的 `model.env` 后重启本站 API。临时停用时将该文件移出原路径再重启，恢复时放回并重启；两种操作均保留网页和浏览器端资料。 |
| 更新后旧标签页缺少模块 | 刷新以载入当前版本入口；确认 `current/public/assets/` 含该版本资源。已归档的旧登录脚本不对外提供。 |
| 换设备后看不到演示记录 | 用原浏览器、原用户配置和相同域名打开；需要跨设备留存时从业务页导出。 |

迁机前备份部署根目录（保留符号链接）、本站 systemd/Nginx 配置与私有配置。私有配置另行加密保存，恢复后恢复 root:root、0600。站点证书沿用服务器既有备份流程。服务器备份不含终端浏览器内的演示记录。
