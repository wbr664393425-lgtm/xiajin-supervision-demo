# 客户汇报演示脚本（v2 · 2026-11-07 汇报版）

建议总时长 10 分钟，按“一个对象、一条线”讲：以张某军（乡镇G和盛村村委会主任）为主线，从一封举报串起信访、图谱、三资、巡察、案卷、智能体与留痕，其余能力在收尾快速带过。

## 演示前 15 分钟

1. 执行 `npm run dev`，用 Chrome 打开 `http://127.0.0.1:5186/#/`，1440×900 或 1920×1080、100% 缩放。使用展示账号 `admin` 和密码 `admin888` 登录工作台。
2. 右上角“管理员”菜单 →「重置数据」→「确认重置」。
3. 看左侧栏底部“智能引擎”：绿点“纪检大模型在线”即网络正常；若显示“离线引擎运行中”，进入 纪检智能体 › 纪检助手点刷新按钮重新检测。会场网络不稳时备好手机热点；断网时系统自动改用离线引擎，界面不报错，演示可照常进行。
4. 顶栏「智能助手」→「全景研判」先跑一次“张某军”确认通畅，然后再重置一次数据。

## 口径（被问到时这样答）

- **AI 边界**：AI 只提疑点、出初稿、给参考；定性、量纪、审批与处置由纪检干部决定，每一步都有人工确认节点并写入审计日志。
- **大模型与数据安全**：当前汇报环境已联调大模型服务；正式部署时大模型、知识库与业务数据全部运行在政务内网，模型本地推理，数据不出内网（见 安全与管控 › 部署与分期）。
- **地图**：地图保留夏津县轮廓，乡镇A至乡镇N的名称、位置及所列疑点均为演示样例。
- **数据来源**：页面中的村居、人员、单位、金额与材料均为样例；与业务系统、政务共享数据的对接状态见 安全与管控 › 数据对接，如实标注“已联调 / 样例数据 / 预留接口 / 待部署”。扫描件识别、录音转写当前使用样例材料，正式部署接入内网 OCR 与语音服务。

## 主线：张某军一条线（约 8 分钟）

0. **能力全景（20 秒）**：工作台 › 能力全景，一屏讲清 8 个业务模块、全部功能和“AI 出疑点与初稿、人来决定、全程留痕”三条原则；顶栏切换模块、左侧点具体功能，任何页面两次点击可达。
1. **工作台（40 秒）**：问候栏读出今日超期任务与红色预警数；点县域风险图中红色的“乡镇G”进入风险一张图，右侧可见和盛村相关疑点。讲：线索、疑点、任务在一张图上汇总，趋势含已办结归档。
2. **信访登记（70 秒）**：信访研判 › 线索登记解析（打开即显示一份已解析样例）→ 点「网络举报」重新载入一封 269 字的口语化举报 →「智能解析」。讲：被反映人、单位、问题类型、时间、三笔金额、诉求一次抽出，原文同步高亮，点要素可回到原文；风险初筛为红色预警。可改一项要素后「人工确认并入库」。
3. **关联图谱（60 秒）**：切到「线索关联图谱」→「只看多次被举报」→ 点“张某军”。讲：两条线索指向同一人、同一合同“和盛村场地租赁”和禾川农机服务社；关联只说明资料中同时出现，不代表利益关系成立。
4. **智能体全景研判（120 秒，重点）**：在张某军卡片点「交给智能体全景研判」。右侧面板依次显示：检索信访线索库 → 比对大数据监督疑点 → 阅读巡察台账 → 查询关联图谱 → 检索案卷与知识库 → 纪检大模型起草初核方案 → 边界自检。每一步下方的标签可点击直达原始记录。方案生成后点正文中的引用角标回到出处，再点「生成初核任务」。讲：智能体把分散在五个模块的资料自动汇总成方案初稿，用时约 20–30 秒；人工确认后才形成任务。
5. **三资穿透（60 秒）**：点步骤里的“到期未收疑点”标签或进入 穿透监督 › 农村三资 → 「和盛村场地租金到期未足额收取，差额 24,000 元」→ 证据对照 → 生成核查任务；在「合同与流水比对」页签点「合同、票据照片识别」可跳到 纪检智能体 › 多模态识别，展示合同照片识别与台账比对。
6. **巡察阅卷（60 秒）**：智能巡察 › 台账批量阅卷（其余 5 份台账已阅，只剩和盛村决策记录待阅）→「批量智能阅卷」→ 打开“和盛村集体场地出租决策记录”，看“先签合同后补会议”“到会不足三分之二”的原文定位 → 问题归类提炼生成报告初稿。
7. **案卷与文书（60 秒）**：审理案卷 › 文书起草校核，页面已预置张某军案审查调查报告初稿 →「载入含笔误示例」→「校核」→ 逐条定位 →「一键修正」。可再切到「证据链校验」「类案推送」。
8. **审计留痕（20 秒）**：安全与管控 › 审计日志，看到刚才的解析、研判、任务生成全部留痕；回到工作台，办理中任务数已增加。

## 历史记录：v1 演示脚本

建议总时长约 7 分钟。全过程使用内置虚构样例，不录入真实业务材料。以下是现场操作路线与观察点，不替代实际功能验收记录。

## 演示前准备

1. 启动 `npm run dev`，打开终端实际显示的本机地址；默认是 `http://127.0.0.1:5186/#/`。
2. 使用 1920×1080 或 1440×900 桌面浏览器，保持 100% 缩放。
3. 点击左下角“重置”→“确认重置”，回到初始样例；确认无已有核查任务。
4. 顶栏“演示导览”可打开六步提示；导览只提供路径，由演示人员主动操作。

开场用语：

> 今天展示的是本地演示平台。所有人物、单位、材料和金额均为虚构。AI 负责整理材料、发现待核事项和提供依据，核查、处置和销号由工作人员确认。

## 第一步：从监督总览找到工作入口｜约 40 秒

**操作：**

进入“监督总览”，浏览待核查疑点、高关注线索、处理中任务和已完成核查；切换“最近 7 天”和“近一个月”。在待处理事项中打开“集体场地租赁款到账情况待核对”（`XF-2026-0108`）。

**讲解：**

> 总览回答两个问题：当前有哪些待关注事项，下一步由谁处理。趋势与待办来自同一份演示业务数据，后续形成任务、完成核查时会同步改变。区域矩阵仅是分布示意，不是真实 GIS 热力图。

**观察点：**进入信访页后，对应线索被选中，原文与所属区域显示一致。

## 第二步：辅助研判，回到原文看依据｜约 75 秒

**操作：**

在“信访线索研判”中先展示中间原始举报材料，点击右侧“开始辅助研判”。等待要素提取、相关线索比对与建议生成；查看合同编号、金额及原文高亮。点击“发现 1 份疑似相关材料”，对照两份材料与匹配依据。

**讲解：**

> 两份材料反映同一集体场地，合同编号都是 SZ-HT-2026-018，年度租金均为 36,000 元。系统提示可能相关，并列出原文；它不会按举报次数认定问题成立，也不会直接删除重复材料。

**观察点：**线索由“待研判”进入“待人工确认”；右侧保留来源、比对规则与待核问题。此时尚未生成任务。

## 第三步：人工确认，形成可办理任务｜约 50 秒

**操作：**

在材料对照窗口点击“人工确认合并”。返回后点击“人工确认 · 转核查”，选择“第一监督检查组”与截止日期，点击“确认并生成核查任务”。打开侧栏“我的核查任务”，展示任务编号、责任组和期限。

**讲解：**

> 相关材料在人工确认后关联归并，原始来源继续保留。正式进入核查也要由工作人员确认责任和期限，系统才会建立任务，并记录操作过程。

**观察点：**主线索进入“处理中”，相关线索进入“已合并”，核查任务列表新增一项，研判页面显示关联任务。

## 第四步：三资穿透，逐项核对合同与到账｜约 90 秒

**操作：**

进入“农村三资监督”，选中 `SZ-HT-2026-018`“和盛村集体场地”。点击“开始智能核验”，展示“合同要素识别 → 收款流水匹配 → 规则比对 → 疑点汇总”。查看“合同到账关联不完整”疑点，打开证据对照，再点击“发起人工核查”，确认责任人员与期限。

**讲解：**

> 合同约定应收 36,000 元，目前已关联到账 12,000 元，待核对差额为 24,000 元。这里提示“到账关联不完整”，还要查完整回单、漏录情况及补充约定，不能直接把差额认定为欠缴。每项疑点都有数据来源、命中规则和待核问题。

可短暂切换其他合同，展示价格参考偏离、合同到期和相同凭证引用等不同规则，不逐条创建任务。

**观察点：**所选疑点进入“处理中”，新增一项农村三资核查任务，金额基础数据不被任务操作改写。

## 第五步：巡察材料到整改复核与销号｜约 120 秒

**操作：**

进入“巡察与整改”，点击“批量辅助阅卷”；选择“和盛村集体事项议事会议纪要”，查看“议事记录关键要素不完整”的原材料摘录、检查事项与建议附件。点击“人工确认，生成整改任务”，确认责任单位与时限。

进入“整改复核”后，先选“简略说明”，展示回应覆盖不足及缺少佐证的提示；再选择“完整说明 + 佐证”，点击“提交整改复核”。人工查看内容后，点击“人工复核通过”。

**讲解：**

> 纸面材料不完整只是需要核查的线索。整改也不能只写一句“已整改”：要说明如何回应原问题，并补充佐证。辅助比对帮助工作人员定位缺口，最后仍须人工复核，系统才销号。

**观察点：**问题依次进入“待整改 → 整改中 → 待复核 → 已销号”；简略说明不会使销号条件成立；完整说明经人工确认后，关联任务进入“已完成”。

## 第六步：返回总览，验证同一条业务链｜约 45 秒

**操作：**

返回“监督总览”，查看处理中任务、已完成核查和待核查疑点；打开“我的核查任务”与“操作留痕”，展示信访、三资、巡察的来源和状态。刷新页面，确认当前演示进度继续保留。

**讲解：**

> 材料、疑点、任务与整改共用一套业务状态，因此总览能看到刚才的操作结果。系统保留人工确认节点及来源，辅助整理工作，不替代事实核查与业务判断。

按上述路径各创建一项任务，并仅完成巡察复核时，预期可看到 **2 项处理中任务、1 项已完成核查、3 项待核查三资疑点**。若额外操作了其他任务，数字应以当前业务状态为准。

## 备用展示｜时间充裕时追加，不计入主线

- **案卷审理助手：**“开始校核”→定位日期、金额、承办人员问题→人工“采纳建议”→“生成摘要初稿”→复制或导出文本。
- **纪检 AI 助手：**任选“信访摘要 / 法规检索 / 材料润色 / 会议纪要”，编辑输入并“开始处理”，查看来源和待确认事项。
- **能力中心：**打开任一能力卡片，查看业务输入、演示比对及数据授权前提，说明分期方案仅为建议。
- **材料录入：**使用粘贴文本或 `.txt`。展示图片/PDF时，主动说明该入口使用内置样例模拟解析，未对任意附件执行真实 OCR。

## 现场恢复

遇到演示状态与脚本不同，优先检查是否已有任务、线索是否已合并，或浏览器是否切换了主机名/端口。需要从头开始时使用左下角“重置”，在确认窗口确认后重新进行。不要在流程中直接清空浏览器全部数据，以免影响其他页面或服务。
